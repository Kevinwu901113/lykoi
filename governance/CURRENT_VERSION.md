## 此次只修三处边界与一个依赖

1. **Mind 语义拒绝不再直接毁掉业务回合。** 明确的输入/证据/快照/事件拒绝返回 observation，Conversation/Wake 用同一 Cognition 的既有步数上限纠正；被拒绝那步的回复、工具或承诺不执行。仍保持原子回滚、版本约束；IO/数据库故障继续失败。审计新增安全错误码。生产 S2 仅留 Error，无法还原具体哪条校验；此处是由代码与可复现测试证实的共享断点，不能声称已证明 S2 的确切异常。
2. **没有真实 pending 就不记成等待用户。** 静默期、发送失败等返回明确系统回执；已有真实 pending 继续等待。未修改 kernel 的拒绝、静默期或审批规则。
3. **只改定时正文可保留到期时间。** 更新现有 Task 时 `message:{text}` 直接复用存储中的 dueAt；明确改时刻才提供 delaySeconds。新建仍需要延迟。不增加计时器或文本意图识别器。
4. **js-yaml 4.3.1 → 4.3.2。** [GHSA-2883-xcg3-v3hh](https://github.com/advisories/GHSA-2883-xcg3-v3hh) 为 high，空 mapping 合并未计入工作量上限，可导致 CPU 拒绝服务。本仓实际调用在部署 YAML 配置装载；未发现 Telegram 正文直接进入该解析器。只改 profile 的精确版本和 lockfile，include 传递依赖复用同一 4.3.2。安装后 npm audit 为 0；未使用 force 升级。

验证：候选版本全量 1,256 项：1,245 通过、0 失败、11 跳过；typecheck 通过。针对性测试覆盖拒绝后不执行旧工具/不提前登记承诺、一次真实 Task 登记、同事务回滚、存储故障传播、纠正次数有界、审批静默期/已有 pending/发送失败、正文单改保留精确 dueAt、空 mapping 合并计费。历史初次沙箱监听 EPERM 和编写中失败保留于本机日志，不计为最终通过。
