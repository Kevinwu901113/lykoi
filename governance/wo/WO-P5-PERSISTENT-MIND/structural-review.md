# Mind 总体检查与结构修正

状态：按所有者“先总体检查，检查完就修”实现。基线 e25100b + ecc761c 验收脚本。未修改 kernel/gate；不合并、不部署。

## 检查结论

检查覆盖模型输出→Conversation/Wake→MindStore→工作集选择→历史读取→Task outbox→后续理解，以及旧 Thought/自主笔记/Integration 的职责。问题不只在模型的一次 null 或版本填错：

- 持久记录类型直接用作模型写协议，把并发版本控制委托给模型；实际上框架已有本次读取快照。
- status 与 open 是两个可独立修改的生命周期真相。resolved 又直接导致默认工作集消失，放大了提前结束的语义错误。
- mind.read 支持历史查询，但下一次认知仍只读默认工作集，无法保证更新所依据的版本就是本次实际展示的记录。
- record_note/tend_inner 仍是 Mind 之外的内省写通道。record_note 的候选说明称不消耗行动预算，统一循环却需要一步，模型在额度耗尽后仍会选择它。
- 工作集没有优先对齐待处理 Task 事件；明确的偏好也可能因为“已解决”而不再被看见。

原有 Task 来源传递、outbox 原子性、请求槽和旧 Thought 退休机制保持有效。本次不新增队列、评分器、关键词审查、语义自动合并或普遍重试。

## 决策与实现

1. 拆开 MindUpdate 与 MindRecord。模型提交完整语义字段；revision/status/updatedAt 由运行时负责，即使旧响应携带这些字段也不能控制数据库。更新按本次 MindView 的版本比较，真实并发冲突仍整事务回滚；未读到的旧 ID 不能当新记录覆盖。
2. open 采用非空字符串或 null，作为是否解决的唯一依据。status 只读派生；对照研究完成不等于原对象证据充分。模型仍负责语义判断，框架不靠关键词推断真假。明确偏好持续参与工作集；最近的已解决记录可利用剩余位置保留上下文。
3. 成功的 mind.read 查询在各自认知循环内保存，并在后续调用前刷新。无全局查询缓存、无共享版本锁。待处理事件关联记录优先参与默认工作集。
4. Mind 模式退休 record_note/tend_inner，所有思考内容统一进入 mind。遗留未装配 Mind 的入口维持原行为。每步从同一候选构造函数展示本拍剩余执行步数，收尾仅展示内部思考选项；仍保持“未执行的动作不能计为已执行”的原预算语义。
5. 旧 Mind 记录一次性迁移，保留内容、来源和显式 released，修正旧矛盾生命周期，版本只增加一次。旧 Thought 表继续只读迁移，Integration 仍负责经历与叙事。

取舍：运行时不再允许模型随意填写 released 状态；原有 released 历史保留并可搜索。没有引入新的语义归档动作。真实冲突仍会失败并留待后续认知读取重做；不掩盖并发覆盖，也不以部分提交吞掉事件。语义上错误关闭的风险不能靠字段设计完全消除，因此保留真实模型验收。
