# WO-L1 · 档案 / 原料分离 —— 前因、内容、后果

**给 Kevin 审阅。** 学习层 v2 重构的第一单。本文件 = 证据链 + 要做什么 + 会变什么 +
可直接派发的工单正文。

## 一、前因（证据链，按发现顺序）

1. **起点**：Kevin 问"还有什么是我们没用上的"。
2. **闲置清点**发现：她 **1844 次自主醒来、59 条观察笔记，但 insights 停在 2026-06-15**——
   **55 天没形成过一条新洞察**。
3. **我第一次诊断错了**：以为是"代谢失衡"（每天产生 ~95 条、只消化 ~61 条）。
4. **深挖推翻**：`pending_experiences()` 的 SQL 写着
   `WHERE integrated = 0 AND source <> 'environment'`，docstring 明写
   "W1 environment 沉淀明确不进入 nightly"——**感知是被设计排除的，不是被饿死的**。
   非感知经验 3690 条已消化 3674 条：**她把该消化的都消化了**。
5. **内容分析揭示真问题**（本单的直接依据）：

   | 消化队列里的东西 | 条数 | 均长 | 性质 |
   |---|---|---|---|
   | `action_result` 空壳（≤80 字符） | **1530** | 29 字符 | "ok/done"级记账 |
   | `wake_action`（她的决策理由） | 1573 | 189 字符 | 思考轨迹，非外部输入 |
   | `thought_lapse` / `silence` | 428 | — | 内部状态 |
   | **`conversation`（与 Kevin 的接触）** | **116** | 128 字符 | **唯一的外部输入** |
   | 合计队列 | **3690** | | |
   | *（被排除在队列外的感知）* | *1178* | *402 字符* | *关于 Kevin 生活的唯一来源* |

   > **她的消化队列里只有 116 条（3.1%）是与外部世界的接触。
   > 而 1178 条关于你的感知，被挡在队列之外。**

6. **关切数据印证了后果**：她的头号关切是"低强度内部动作的负载边际影响阈值"
   （点亮 **1381** 次，活跃至今）；前四名里三个是她自己的内务；关于 Kevin 的关切
   只有两条，且都是"他没回应"；摄影/影视两个兴趣**点亮 0 次即释放**。

   **诊断：不是关切机制坏了，恰恰是它工作得很好——她被喂什么，就想什么。
   输入决定注意力。**

7. **Kevin 定案**（2026-08-10）：①一次到位重构，不做补丁式修复；
   ②她自己的决策理由落档案层可查、不进消化预算；③给他一个"我希望你留意 X"的入口。

8. **学习层 v2 设计**据此成形；**L1 是它的第一块**，也是唯一不依赖任何新机器的一块。

## 二、这一单要做什么

**一句话：把"档案"和"待消化原料"分开——她现在把两者混在同一张表里。**

**唯一分流判据：这条记录里有没有外部世界注入的新信息？**

| 去向 | 内容 | 条数 |
|---|---|---|
| **原料池**（进消化预算） | 对话 + 感知 + `action_result` 中含实际返回内容的（>80 字符） | **1337** |
| **档案层**（永久可查，不进预算） | 动作空壳、她的决策理由、内部状态记录 | **3531** |

**关键性质**：
- **一条记录都不删**——4868 条全部保留，只是重新分类；
- **不改现有表结构**——用分类影子表（沿用 P2-01 `memory_scopes` 的成功做法），
  不动 append-only 触发器；
- **逆迁移 = 删掉分类表**，回到今天的状态。

## 三、后果

### 会变什么

| | 现在 | L1 之后 |
|---|---|---|
| 消化队列规模 | 3690 条 | 1337 条 |
| 队列中含外部信息的比例 | **3.1%**（116/3690） | **100%** |
| 关于 Kevin 生活的感知 | 0 条可用（被 SQL 排除） | 1178 条在原料池，**可用** |
| 她的记录总量 | 4868 条 | 4868 条（**不变**） |
| 她能不能回想细节 | 能 | 能（档案层可检索） |

### **不会**变什么（重要）

**L1 单独部署，她的行为零变化。** 因为消费这个分类的是 L2（层 1 改造），本单只建分类。
这是刻意的：**先让新分类跑起来、可观察、可回滚，再改动她的消化行为**。

所以 L1 是：**高信息量、零行为风险、完全可逆**。

### 为后面铺什么路

- **L2**（层 1 改造）：消化源从"全部未消化"改为"原料池未消化"，感知自动进入
- **L3**（相关性检索）：档案层成为"她可以回想的过去"，而不是垃圾桶
- **L4**（层 2 专注思考）：跨时间检索的对象就是档案 + 原料池

## 四、工单正文（可直接派发，opus）

```
# WO-L1 · 档案/原料分离 + 分流判据 + 历史回填

设计基准：~/learning_layer_v2_design_2026-08-10.md（§3.1 档案层、§3.2 分流判据、§5 迁移）。
分支 wo/l1，基于活体 main。

## goal

1. 分类判据实现（纯函数，可单测）：
   classify(source, content) -> 'working' | 'archive'
   - 'working'（进原料池）：source in ('conversation','environment')
     或 source='action_result' 且 len(content) > 80
   - 'archive'：其余全部（wake_action / action_result 空壳 / thought_lapse / silence）
   - 阈值 80 定义为具名常量并注释来源（实测 action_result 97% ≤80 字符，均长 29）
   - 判据必须只依赖 source 与 content，不依赖外部状态（保证回填与实时判定一致）

2. 分类存储：新增影子表（照 P2-01 memory_scopes 的做法，不改 experiences 表结构、
   不动 append-only 触发器）：
   experience_class(experience_id PK, class TEXT CHECK(class IN ('working','archive')),
                    classified_at TEXT, rule_version INTEGER)
   带 rule_version，便于将来判据升级时重新分类。

3. 历史回填：对全部 4868 条历史经验回填分类。批量事务、可重入
   （重复执行不产生重复行、不改变已有分类）。

4. 实时分类：新经验写入时同步分类（找到 experiences 的唯一写入点并接上，
   先读代码确认写入点，不要假设）。

5. 查询辅助：working_set_pending(limit, by_salience) 与 archive_search(...) 两个
   只读辅助函数，供 L2/L3 使用。**本单不修改 integrator、不改变任何消化行为。**

6. 逆迁移：downgrade 删除影子表即回到现状。

## forbidden
- 不改 experiences 表结构、不动触发器、不删任何记录
- 不改 integrator / pending_experiences 的现有行为（那是 L2）
- 不新增依赖；不 push；提交留在 wo/l1
- 不要跑全量 pytest（复核方统一跑）；完成后立即 git commit

## manifest 纪律
触及 mind/ 或 memory/ → python3 guardian/startup_verify.py --write-manifest 重签，
报告给出 diff，跑 pytest tests/test_p0_integrity.py 报数
（claude 身份下有 1 个既有假失败 PermissionError: approval_rules.json，如实报告）。

## success_criteria（用合成 fixture，禁止使用真实备份）
1. 判据单测：六类 source × 长短内容的边界用例全覆盖，含 80 字符边界。
2. 回填：可重入（跑两次结果一致）；分类总数 = 经验总数。
3. 实时分类：新写入的经验立即有分类行。
4. 逆迁移后表清单与迁移前一致。
5. **行为不变证明**：integrator 与 pending_experiences 的现有测试全部照常通过
   （本单不该影响它们）。

## required_evidence
git log/diff --stat；判据函数完整代码；影子表 DDL；回填的实际命令与输出；
每条 success_criteria 的测试用例名+结果；manifest diff；
必答硬数字（新增/修改文件数与行数、专项测试通过数、p0 通过数、manifest 条目数）。
```

## 五、风险与回滚

| 风险 | 缓解 |
|---|---|
| 分类判据错杀（把有价值的记录归档） | 判据只依赖 source+content，可单测；`rule_version` 支持重新分类；**归档 ≠ 删除**，L3 检索得到 |
| 回填影响活体性能 | 4868 行、批量事务，实测 Mac 上同规模操作是毫秒级 |
| 影响她的运行 | **L1 不改任何消化行为**，integrator 现有测试必须全过 |
| 判据阈值 80 定错 | 实测支撑（97% ≤80，均长 29，>80 的仅 43 条）；常量可调 + rule_version 重分类 |

**回滚**：删除 `experience_class` 表 → 完全回到今天的状态。代码回滚 `git revert`。
