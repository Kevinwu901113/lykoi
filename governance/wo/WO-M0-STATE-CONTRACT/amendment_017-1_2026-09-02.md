## insights.category 新值 `relationship`

- 现行值集：`persona` / `preference`（Canon 投影，`getInsights` 读）、`focus`（L4 通用结论，
  `FOCUS_INSIGHT_CATEGORY`）、**`relationship`**（L4 从 `relationship_thread` 关切得出的
  相处方式结论，`RELATIONSHIP_INSIGHT_CATEGORY`，正本 `rw.ts`，`lykoi-learn/src/shared.ts`
  持副本，`boundary.test.ts` 对拍逐字相等）。
- 列无 CHECK；值集由代码面约束，不由 DDL 约束（现行为，本件如实记录）。
- 判别式在代码：`concern.kind === 'relationship_thread'`（`RELATIONSHIP_CONCERN_KIND`），
  不在提示词、不在信封字段。
- `(category, content)` 去重语义不变：同一结论文本在不同类别下是两行。

## memory_scopes：TS 体第一个运行期写者

- 写者：`ReadWriteMemory.scopeInsightSubject(insightId, subjectUserId)`（rw.ts），
  调用点仅 L4 `applyConclusion`（relationship 分支）。此前 memory_scopes 只由迁移 / 夹具写。
- 行形状固定：`('insights', <insight_id>, <subject_user_id>, NULL, 'private', 'content')`
  即 `origin_context` NULL、`visibility` private、`sensitivity` content。
- 语义：**实体轴** = "这条结论是关于谁的"。`INSERT OR IGNORE`：一条 insight 只有一个键，
  首次落地钉死，重申不改写、不追加；返回值 = 是否新写。`subject_user_id` FK 到 users
  生效（不存在的 id 抛，不静默）。
- KEY 推导序（l4.ts）：关切自身的 memory_scopes 实体轴 → 否则 `ownerPrimaryUserId()`
  （users 中 role=owner_primary 且 active 的唯一行）→ 皆 null 时**不键控**：结论落为
  category=focus 的普通行并发 `relationship_overlay_unkeyed`。
- 本单只写 `table_name='insights'` 行；不给 concerns / experiences 补写实体轴。

## focus_insight_state 读口两分（状态机不变）

| 读口 | 语义 | 消费者 |
|---|---|---|
| `listFocusInsights(status)` | **全集**，不分类别，一字未动 | L4 状态机全部边（promote / retire / relit / contested / existingConclusions） |
| `promotedFocusInsights()` | active ∧ `COALESCE(insights.category,'') <> 'relationship'`（LEFT JOIN；insights 行缺失 → category NULL → 归此口） | converse 转正结论段（`PROMOTED_INSIGHTS_HEADER`） |
| `promotedRelationshipInsights(subject)` | active ∧ category = relationship ∧ memory_scopes 实体轴 = subject（inner JOIN 两表） | converse overlay 段（`RELATIONSHIP_OVERLAY_HEADER`），subject = `ownerPrimaryUserId()` |

- 两口互斥；并集 = 旧 `promotedFocusInsights`（= active 全集）**减去**无键的 relationship 行。
- **无键的 relationship 行 = 坏数据形态**：两口都不给，但仍在 `listFocusInsights` 全集里，
  状态机照管。产生窗口仅为 L4 三写（upsertInsight → recordFocusInsight →
  scopeInsightSubject，各自事务）之间的进程崩溃；同一结论再次被得出时键自动补上（自愈）。
  复核裁定不为此合并事务边界（review.md §3 偏离 2）。
- 六态状态机、影子期 3 周期、dormant 阈值 30 周期、点亮、contested 路径对 relationship
  行**一视同仁**（增补件 017 全部条款不变）。

## 装配

- 人格块（`#messages[0]`，夜间印记变化时重建）顺序：内核 → 重启叙事 → 纪律 → ask 兜底 →
  转正结论段 → **overlay 段**。overlay 头部逐字
  `你和眼前这个人相处的方式(专注思考里得出、已经站住、只关于这个人的结论):\n`
  （chars 38，sha256 `a0553be7100bd34013ac54ac67b11e3628beb5d0b3e48c3f5f9ac2b2b674c22e`，
  prompts.test.ts B 表第 14 条），行格式 `- {content}`，按 insight_id 升序。
- 空态零字节：subject 为 null、或无行 → 连头部都不出现，人格块逐字节回到本单之前形态。
- 读失败 → `relationship_overlay_read_failed {error_type}` + 零字节，不毁整轮。
- 单 Conversation 实例、单对话者是现体事实；多对话者时 subject 的来源是另一单的结构改动。
