## focus_insight_state.status 六态（mind_schema 17 起）

```sql
status TEXT NOT NULL CHECK (status IN ('shadow','active','contested','revised','withdrawn','dormant'))
```

- 其余列 / 约束 / REFERENCES / 索引 `idx_focus_insight_state_status` 逐字不变。
- DDL 正本单一来源：`packages/lykoi-memory/src/schema.ts`（`STATE_SCHEMA_DDL`），
  夹具 `testing.ts` 与生产创建入口 `init-state.ts` 共用；迁移件 017 的重建
  DDL 与之逐字一致（`rw-insight-dormant.test.ts`「017 up」对列定义段做等值
  断言；表名一截经 `ALTER … RENAME` 后由 SQLite 重写为带引号形态，属 SQLite
  语义，不属文本选择）。
- `dormant` = 转正（active）后久未被 L4 再触达而退出装配的结论：不销毁、
  内容不动、可点亮。与 `withdrawn`（被证据推翻）严格区分。
- 代码面同源枚举：`FOCUS_INSIGHT_STATUS_ENUM`（rw.ts）六态；
  `listFocusInsights` / `setFocusInsightStatus` / `recordFocusInsight` 按它校验。

## 状态机增补（正本：WO-MEM-DECAY-01 order.md §2 D-1..D-8）

| 边 | 产生点 | 判据 / 规则 |
|---|---|---|
| active → dormant | L4 `retireStaleInsights`（每一种周期结尾，与 `promoteDueInsights` 同调用位，排在 `applyConclusion` 之后） | `cycle_id − 上次触达周期 ≥ INSIGHT_STALE_AFTER_CYCLES`（=30，l4.ts 常量，非配置项）；上次触达 = `focus_insight_history` 最后一行的 `cycle_id`（history 空时退回 `updated_cycle_id`）；单位是周期序号不是墙钟；单步，无中间态 |
| dormant → active（点亮） | `recordFocusInsight` 重申一条 dormant 行 | 状态改 active、`updated_cycle_id` / `updated_at` 刷新、`contested_since_cycle` 清空；history 一行 reason `relit`；返回值仍为 false（点亮不是新结论） |
| dormant → contested → revised / withdrawn | 既有 `applyConflicts` 路径 | dormant 进 `existingConclusions` 喂入集（上限 20 不变），被新证据推翻时当场了结，不留到点亮时带着被推翻的内容复活 |

- 不存在 dormant → shadow 的产品路径。状态机无边表，`setFocusInsightStatus`
  仍只校验枚举（现行为，本单不新增禁边逻辑；测试如实钉住）。
- `contested_since_cycle`：迁到 dormant 保留（同 revised / withdrawn）；点亮清空
  （同 active 分支）。
- 装配口 `promotedFocusInsights` 语义不变（= active）；dormant 自然出局；
  converse 装配零改动。
- 其他状态的重申行为一个字不动（shadow 不因重申重新计时）。

## 因果出口 / 事件

- 降档与点亮均走既有 `focus_insight_status` 事件
  `{insight_id, cycle_id, from, to, reason}`，不新增事件类。
  降档 reason 格式 `stale: last touched cycle N, now cycle M (>= 30)`；
  点亮 reason `relit`。
- `FocusSummary` 增 `retired: number[]`。
- 事件计数口径：精确匹配 `"type":"focus_insight_status"` 且 `"to":"dormant"`，
  禁子串 grep。
