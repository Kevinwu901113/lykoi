# 主动额度边界复核与修复

Kevin 在 PR #7 初次交付后要求检查类似问题，并明确授权修复。初次修复遗漏了主动规则建议的 E1 调用方；原先的绿测不覆盖这项预算回归。本文件记录后续修正，以本次最终提交为审阅对象。

## 已修复

- **引用与预算分离。** messenger.send 不再依据模型可填的 reply_to 豁免额度。只有 kernel 验证的 admission 能免预算。有效引用、旧引用、无引用都遵守同一预算判定；在场应答的 E2 仍由设备层绑定对端。
- **主动聊天共用账本。** 直接 messenger.send 与 autonomy.initiate_chat 都调用 kernel/proactive-chat 的现有原子预留。快照读取同一账本；仍是一日一次、跨日保留六小时冷却。通知自身的独立额度不变。adapter 的旧函数名保留为薄兼容出口，重复计数代码删除。
- **主动建议与审批往返分离。** 新的未请求规则建议不再盖 E1，按自主权限规则执行并消耗主动额度；被拦时不出队。真实审批、已发问询的回应/撤回/过期通知沿用审批通信资格。
- **来源统一。** kernel 将真实 dispatch origin 作为 admission 元数据传到资源。notify.owner 不读模型 params.origin，不默认成 system；缺少可信来源明确失败。Conversation 删除重复盖章逻辑，Task 和其他入口无需各做一套覆盖。

复测中还发现 Task 输入同时暴露“宿主负责交付”的说明和内部 delivery:null，语义容易混淆。认知输入现在提供明确 output 契约，内部送达回执仍保存在 Task 供查询和恢复，不混入模型的执行输入。插件回归覆盖输出契约、原请求时间与持久追溯边界。

## 旧账本升级

唯一工作账本为 proactive_chat.json。首次读取会将旧 messenger_outbound.json 的有效时间戳与工作账本合并、排序和有界保留，先原子写入工作账本，再把旧文件改名为 messenger_outbound.json.migrated。若在两步之间中断，再次合并会按时间戳去重，不重置额度；坏账本明确失败，不默认为空。

旧 LYKOI_MESSENGER_LEDGER 配置仍保留作迁移入口，没有新增环境改道。当前生产尚未运行这次迁移。停机回滚旧版前，应将共享账本的当前内容同步回旧 messenger 账本，避免旧代码把缺少旧文件误认为额度未用；不能只恢复过时的 migrated 归档。

## 验证范围

新增实际 Runtime/kernel/resource 与调用方回归：无 E2 的引用无法绕过耗尽额度；直接/排队发送两种顺序互斥且快照一致；旧账本合并后仍耗尽；实际 maybeAskOwner 在额度耗尽时不发不出队、有额度时发并扣额；真实 E1 审批在耗尽时仍送达；三种合法来源由 kernel 传递，伪造 params.origin 无效，自主 notify.owner 仍被拒绝。

定向预算回归 40 项通过。最终全量、类型检查及真实模型样本见 report.md 的后续复核结果。没有新增策略服务、独立调度器、模型关键词路由或自动重试机制。未合并、未部署、未修改生产状态或发送真实 Telegram 消息。
