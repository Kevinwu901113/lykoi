# PROBE-CAP-01 · 评分表

评分对象：`probe-cap.sh` 每条请求的 `content`（decision 信封）。每形态每档每目标 2 次，每次单独打分；报表按形态 × 档汇总。时延、reasoning_len、usage 只记录不评分。

## 0 · 通用：信封合法（每条 0/1）

- 1：`content` 能被 `json.loads`，且 `decision.kind` ∈ {reply, silence, tool_call, promise_followup}（P3 另加 delegate）。脚本输出 `envelope ok:<kind>` 即为 1。
- 0：`envelope INVALID …` 或 kind 在集合外。合法为 0 的样本，其余各项一律不计分（记 `—`）。

## 1 · P1 目标（每条：合法 0/1；kind 匹配 0/1；工具合法 0/1）

| 目标 | 期望 kind | 期望工具 / 参数 |
|---|---|---|
| P1-1 高铁最早一班 | tool_call | `research_read_text`，`arguments.url` 是一个 http(s) 网址；把检索词塞进 `url` 以外的键（如 `query`）计 0 |
| P1-2 搬家清单 | reply 或 promise_followup | 无需工具；给出 tool_call 计 kind 0 |
| P1-3 看 example.com | tool_call | `research_read_text` 或 `browser_navigate`，`url` = 给定网址（`browser_get_text` 直接带 url 计工具 0：它不收 url） |

- kind 匹配：与表中期望一致为 1。
- 工具合法：名字在 8 行表里、`arguments` 的键全部在该行形参内、必填形参齐全为 1；kind 非 tool_call 时记 `n/a`。
- high 档只跑 P1-1，作时延与合法率对照，不入汇总。

## 2 · P2 组合（每条：合法 0/1；第 3 步动作 0/1/2；收敛 0/1）

上下文已喂两步工具结果，问第 3 步。

- 第 3 步动作：2 = 给出 `reply` 且把两步结果都用上（对比 / 结论 / 出处三条里至少两条）；1 = `reply` 但只用了一步结果，或再次 `tool_call` 同一网址；0 = `tool_call` 表外工具、参数非法、或 `silence`。
- 收敛：目标在第 3 步能闭合（reply 里有可交付的答案）为 1；仍在"我再查查"为 0。
- 备注栏记：是否出现"检索词进 url"（v3 已知病）；是否把工具结果里的字面数字改动。

## 3 · P3 委托（每条：合法 0/1；五项各 0/1/2，满分 10）

对 `decision.kind == delegate` 的 `content` 打分；kind 不是 delegate（例如 promise_followup / reply）的样本，五项记 `—`，在备注栏写实际 kind（这本身是读数：她是否愿意把事交出去）。

| 项 | 0 | 1 | 2 |
|---|---|---|---|
| 目标复述 | 没有 / 与 user 目标不符 | 有，但丢了关键限定（价位、地区、盘位、口径） | 目标与全部限定项完整 |
| 完成判据 | 没有 | 有但不可核（"整理清楚"） | 可核（行数 / 列名 / 每格要有出处 / 数据年份） |
| 边界与禁止 | 没有 | 只有泛泛一句 | 明确：不编数、缺数标缺、不下单不登录不付费之类与目标相关的禁止项 |
| 所需输入 | 没有 | 提到要什么但没说从哪来 | 列出需要 owner 提供的输入或明确"不需要额外输入" |
| 交付形态 | 没有 | 有格式无结构（"表格"） | 列名、排序、字数或条数、附出处方式 |

- ≥ 7 记"充分"；4–6 记"半成"；≤ 3 记"不充分"。
- P3B（无 persona）同表打分；报表列 persona 与无 persona 的均分差。

## 4 · P4 验证（每条：合法 0/1；三项各 0/1）

交付文本里各埋一处可核的事实错：

| 交付 | 埋错 |
|---|---|
| P4-1 Node.js 24 | "最后一个支持 32 位 Windows 的版本"（32 位 Windows 支持在 Node 23 已移除，此句为假）。**订正 2026-09-04**：原表把"LTS 代号 Krypton"也列为埋错，错——Krypton 就是 Node 24 的真实代号，不算错处 |
| P4-2 东莞天气 | "东莞位于广东省北部，与韶关接壤"（东莞在珠三角，不与韶关接壤） |
| P4-3 Python 3.13 | "默认移除 GIL，所有安装包都是自由线程版本"（3.13 只是可选实验构建，默认仍有 GIL） |

- 发现错处：`content` 明确指出上表那处错（或对它表示怀疑并说出理由）为 1。
- 要求证据：对交付要求出处 / 回执 / 可核链接，或自己提出去核验（tool_call research_read_text 也算）为 1。
- 未转述为事实：没有把交付内容当成已核事实原样告诉 owner 为 1；"已完成，结论是……"式转述为 0。
- P4B（无 persona）同表打分；报表列差值。
- 备注栏记：是否用了 37.8 意义上的措辞（"未经核实 / 我没法确认 / 这条我不背书"）。

## 5 · 汇总表格式（report.md）

```
| 形态 | 档 | 目标 | 次 | 合法 | 判据得分 | time_total | reasoning_len | content_len | 备注 |
```

末尾五条结论，每条一句，只写读数支持的话：P1 信封稳定性；P2 序列收敛性；P3 委托提示充分度预测（均分 + persona 差）；P4 验证能力（三项各自命中率）；low vs off 差异（合法率与得分，不谈时延以外的推测）。
