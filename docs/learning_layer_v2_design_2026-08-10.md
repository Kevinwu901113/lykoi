# 学习层 v2 · 完整重构设计 · 2026-08-10

- **地位**: Kevin 定案"一次到位、不做补丁式修复"后的完整结构设计。待他评审。
- **依据**: `learning_layer_restructure_analysis_2026-08-10.md`（分析）+
  `consolidation_plane_design_2026-08-10.md`（早期框架，本文件取代其实施部分）。
- **兑现白皮书**: 13 章（离线巩固/做梦）、14 章（学习分层）、6.7（记忆类型）。

## 0. Kevin 的三条定案

1. **一次到位**：整体看结构，不做补丁式修复，不行就直接重构。
2. **她自己的决策理由（`wake_action`）落档案层可查，但不进消化预算**——
   它是她的思考轨迹，不是外部世界的输入。
3. **给 Kevin 一个"我希望你留意 X"的入口**。

## 1. 不变量（重构中绝对不能破坏的）

白皮书结论章：**可以重构她的软件身体，但不能未经判断地丢弃她已形成的经历、关系和身份。**
落到本设计：

| 不变量 | 保障方式 |
|---|---|
| 4868 条经验一条不丢 | 全部进档案层，只重新分类，不删除 |
| 510 个叙事版本、9 个关切、6 条 insights | 原样保留，结构不动 |
| 叙事连续性门 | 层 1 保留现有机制，不改 |
| append-only 审计与既有触发器 | 不动 |
| 她运行不中断 | 迁移可逆；层 2 是新增，出问题停掉即可 |

## 2. 整体结构

```
  全部记录 ──分流判据──┬──> 【档案层】永久保存 / 可检索 / 不进消化预算
   (动作日志·决策理由    │      ← 她想回想细节随时能查
    ·感知原始·对话·收据) │
                       └──> 【原料池】含外部世界注入的新信息者
                                │
                ┌───────────────┴────────────────┐
                ▼                                ▼
      【层1 日常整合】时间流·全覆盖        【层2 专注思考】关切驱动·跨时间
      (现有 integrator 改造)              (新建)
      产物: 叙事 / 情绪调节 / 关切          产物: insights / procedures / 规则建议
                │                                ▲    │
                └──────── 产出关切 ──────────────┘    │
                                                      │
                          Kevin 指定关切 ──────────────┘
                                (经 messenger)
                                                      │
                                          ┌───────────┴───────────┐
                                          ▼                       ▼
                                   自动放行(知识/能力)      必须问 Kevin(权限/规则)
```

**一句话**：层 1 回答"我这段时间过得怎么样"，层 2 回答"我明白了什么"。
两者共享原料池，通过**关切**耦合。

## 3. 组件详述

### 3.1 档案层（新）

- **收什么**：全部记录，无例外（动作日志、她的决策理由、感知原始事件、对话、执行收据）。
- **不做什么**：不进消化预算、不占 LLM 调用、不参与叙事。
- **可检索**：按时间 / 来源 / 实体 / 关键词。她可以"回想上周我在忙什么"（层 2 检索它）。
- **落地**：不新建库——`experiences` 表加分类标记（沿用 P2-01 影子表思路，
  避免改动 append-only 结构），或新增 `experiences_class` 影子表。
  **决定权交实现期，但必须不改现有表结构**。

### 3.2 分流判据（决定什么进原料池）

**唯一判据：这条记录里有没有外部世界注入的新信息？**

| 记录 | 判定 | 依据 |
|---|---|---|
| `action_result`（1573 条，97% ≤80 字符，均长 29） | **档案** | "ok/done"级记账，零信息 |
| `wake_action`（1573 条，均长 189） | **档案**（Kevin 定案 2） | 她的决策理由 = 思考轨迹，非外部输入 |
| `conversation`（116 条） | **原料** | 与 Kevin 的交互，最高价值 |
| `environment`（1178 条） | **原料** | 关于 Kevin 生活的唯一来源 |
| `thought_lapse` / `silence` | 档案 | 内部状态记录 |
| 执行收据（新，来自 Gateway） | 原料 | 客观结果 |

**例外通道**：`action_result` 中长度显著超出模板（>80 字符，实测 43 条）的，
说明含实际返回内容 → 进原料池。**判据是内容不是来源**。

**预期效果**：原料流从 4868 条降到约 1337 条（对话+感知+长结果），
信噪比从 ~35% 提到 **~95%**；而她**一条记录都没丢**。

### 3.3 层 1 · 日常整合（改造现有 integrator）

**保留**：七步流程、四操作、连续性门、关切取舍、`INTEGRATION_EVERY_WAKES` 节律。

**改造三处**：
1. 原料来源从"全部未消化经验"改为"**原料池**未消化项"（去掉 `source <> 'environment'`
   的硬排除，W1/W2 分期作废）；
2. 容量 K 重新标定——原料池小了 3.6 倍，K=30 可能变成"每晚都能清空"，
   **实现期按实测重定，目标是不积压**；
3. 显式产出关切时标注 `origin`（见 3.5）。

**不改**：叙事重写逻辑、连续性门、情绪调节——**这是她唯一活着的学习回路，不冒险**。

### 3.4 层 2 · 专注思考（新建）

**触发**：每 N 个整合周期一次（N 待定，起步建议 1，即每晚一次），或关切压力触发。

**流程**：
1. **选关切**（见 3.5 选择策略）
2. **跨时间检索**该关切的相关原料（见 3.6）——**不限于未消化项**，
   已消化的、几个月前的都可以重新调用
3. 一次 LLM 调用：推进该关切 → 产出/修订结论
4. 落产物 + 血缘（见 3.7）+ 过门（见 3.8）
5. 更新关切状态（有进展 / 无进展 / 可释放 / 派生新关切）

**反刍防护**：同一关切连续 M 次深挖无新结论 → 强制冷却 K 个周期；
冷却次数累计超阈值 → 建议释放。（#8 关切已被点亮 1381 次——没有这条会一直钻。）

### 3.5 关切的生命周期

**三个来源**（`concerns.origin` 字段已存在，直接用）：

| origin | 来源 | 权重 |
|---|---|---|
| `emergent` | 层 1 从原料中涌现（现有机制） | 常规 |
| **`owner_directed`** | **Kevin 明确表达的关注点**（Kevin 定案 3） | **最高** |
| `derived` | 层 2 深挖时派生的新问题 | 常规 |

**Kevin 的入口不需要新协议**：他在 Telegram 说"我最近在做 X，你留意一下"，
层 1 消化这条对话时识别为关注表达 → 建 `origin='owner_directed'` 的关切。
（她也可以主动问"最近要我特别留意什么吗"。）

**选择策略（层 2 每次挑哪个）**：
`owner_directed` 优先 → 其次按 `lit_count`（反复被点亮 = 反复出现）→ 排除冷却中的。
**首版用规则，不接 bandit**（见 4.2）。

**死亡**：现有 `release_concern` 机制保留；新增"深挖无进展"作为释放理由之一。

### 3.6 跨时间相关性检索（本设计唯一的新机器）

**最小实现（起步）**：实体 + 关键词索引
- 实体轴：`memory_scopes.subject_user_id` / `origin_context`（**P2-01 已建**）
- 时间轴、来源轴：现有字段
- 关键词：关切的 title/description 对原料内容做匹配

**升级路径**：向量检索（贵、更好），**本版不做**，但接口设计成可替换。

**为什么够用**：起步阶段关切只有个位数，原料池约千条量级，实体+关键词足以召回。

### 3.7 产物与血缘

| 产物 | 落位 | 血缘 |
|---|---|---|
| insights（关于 Kevin/世界的知识） | `insights`（现有表） | `note_insight_links` 泛化 |
| procedures.reliability | `procedures`（P2-01 已建） | 同上 |
| 规则建议（常设授权候选） | 建议队列，**不直接写规则** | 同上 |

**通用血缘表**：`(产物类型, 产物 id, 原料类型, 原料 id, 周期 id)`。
要求：**任何结论都能回溯到具体原料**（白皮书可审计要求）。

**双向性（硬要求）**：每类产物必须有修订/撤回路径。
新原料与既有 insight 冲突 → 标 `contested` → 下一周期仍冲突 → 修订或撤回，
**保留历史**（她曾经这么认为过，属于身份连续性）。

### 3.8 门（强度随"产物影响什么"递增）

| 产物影响 | 门 |
|---|---|
| 叙事 / 情绪 | 连续性门（现有），自动 |
| 知识（insights） | 影子期 → 自动放行 |
| 能力自评（reliability） | 自动，但只能由客观收据更新（单写者） |
| **她自己的权限边界** | **必须 Kevin 批准，永不自动** |

**铁律**：她可以**观察到**"这类事 Kevin 总是批准"、可以**建议**变成常设授权，
但**绝不能自己写进 `approval_rules.json`**。与 `policy_core` 既有设计一脉相承。
问的通道 = messenger（与审批解释器 S2 共用）。

### 3.9 遗忘

- **档案层**：不遗忘（长期保留，是她"回想细节"的能力基础）。
- **原料池**：消化后退出；超期未消化且低价值 → 退回档案（不删）。
- **结论**：可修订/撤回，历史保留。
- **感知原始流**：白皮书 7.3 的 7 天保留期照旧（提炼结论不受限）。

## 4. 现有资产的处置

### 4.1 保留原样
现有 integrator 的叙事/情绪回路、连续性门、concerns 机制、narrative_versions、
既有 6 条 insights 与 4 条叙事线索。

### 4.2 显著性 bandit：**降级留位，不接**
它当初解决的是"稀缺消化预算里优先谁"。**原料池瘦身 3.6 倍后这个问题基本消失**。
新结构里唯一可能的位置是"层 2 选哪个关切"（explore/exploit），
但那需要"这条 insight 后来有用吗"的反馈，而反馈源只有 Kevin、极稀疏。
**结论：首版用规则选关切，bandit 保留数据不删、不接入决策路径**；
待层 2 跑一段时间、有了真实反馈样本再评估。

### 4.3 W1/W2 分期：**作废**
感知直接进原料池。当初"防 OCR 噪声稀释 nightly 吸收"的顾虑，
由分流判据（3.2）与关切驱动检索（3.4）从结构上解决，不再需要分期闸门。

### 4.4 `INTEGRATION_CAPACITY_K=30`：重新标定
原料池瘦身后按实测定，目标"不积压"。

## 5. 迁移（历史数据）

**原则：只重新分类，不删除、不改现有表结构。**

1. 建分类影子表（或加标记列），对 4868 条历史经验按 3.2 判据回填分类；
2. 1178 条历史感知从"被排除"变为"档案 + 可被层 2 检索"——
   **不补做消化**（补 1178 条积压是伪需求：层 2 需要时会检索它们）；
3. `integrated` 语义不变，历史值保留；
4. 逆迁移：删除分类表即回到现状。

## 7. 风险与开放问题

1. **层 2 的 LLM 成本**：每晚多一次调用，需配额；深挖失败（无结论）也要计入。
2. **关切偏斜的自我强化**：`owner_directed` 优先能纠偏，但如果 Kevin 长期不指定，
   她仍可能钻内务。**建议加一条硬规则：层 2 必须定期（每 M 次）挑一个
   `subject_user_id=user_001`（关于 Kevin）的关切**——防止她只顾自己。
3. **检索召回不足**：实体+关键词可能漏掉语义相关但用词不同的原料。首版接受，
   接口留可替换。
4. **"她的决策理由不进消化"是否让她失去自我认识？** Kevin 已定案落档案。
   缓解：层 2 可以主动检索档案（例如关切是"我的负载管理"时），
   **档案不是垃圾桶，是可调用的记忆**。
