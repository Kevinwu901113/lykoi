# Lykoi Composer 首版

状态：当前 main 的唯一受维护运行时。2026-10-02 经所有者确认，旧个人 Agent 运行时已整体退役，详见 [退役说明](legacy-retirement.md)。

面向有基础能力的技术开发者，在 WebUI 中选择已注册组件、配置和连接，组成一个 Agent。Core 是一次模型计算组件，执行循环位于运行策略层；人格、复杂记忆、自主唤醒和聊天渠道都不是必需依赖。

## 启动与最小演示

需要 Node.js 24 或更高版本。在仓库根目录执行：

```sh
npm ci
npm start
```

打开 `http://127.0.0.1:4310`，依次：

1. 点击“加载示例”：提示词 → Core → 人工输入 → 输出。
2. 点击“保存版本”，打开顶部“试运行”，再“新建实例”。
3. 填写本次输入并运行，观察节点回执和运行时间线。
4. 在人工等待处输入确认后的内容，提交并继续，查看最终结果。
5. 修改提示词并保存 v2。已创建的 v1 运行仍固定原定义，新运行使用 v2。

示例明确使用离线演示模型，仅验证装配链路，不伪装真实联网调研结果。可以从组件库添加节点、拖动节点标题布局、通过输入输出端口拖动或点击连线。已有输入将被替换；环路和不兼容类型立即拒绝。也可在右侧配置栏选择输入来源、绑定模型与工具。连接按依赖顺序串行执行，支持带出口的条件分支与互斥汇合；不支持并行调度、并行结果收集或循环图。普通节点只有一个控制输入，互斥汇合可连接多个候选路线。

状态默认位于 `var/composer/`，包括独立 SQLite 数据库和实例工作区。`npm start` 与 `npm run composer` 使用同一入口；旧 Panel 和 Cordis 生产入口已退役。

## 模型与资源

Core 绑定生成模型资源，决策计算绑定决策模型资源，HTTP 请求绑定服务资源。两个 Core 显式绑定同一资源 ID 时，在同一实例内共享资源；另一个实例创建独立资源对象与文件工作区。模型、工作区配置属于定义；密钥和物理工作区路径属于部署。

左侧“设置”中的共享资源可切换为 OpenAI 兼容接口，填写接口基础地址（例如 `http://127.0.0.1:8080/v1`）、模型名和可选凭证句柄。这里是通用适配接口，不限定使用本机模型。

需要密钥时，在仓库外创建权限受限的本机部署 JSON 文件：

```json
{
  "stateRoot": "/absolute/path/to/composer-state",
  "port": 4310,
  "credentials": {
    "provider-main": "REPLACE_LOCALLY"
  }
}
```

```sh
npm run composer -- /absolute/path/to/deployment.json
```

组件资源中的 `credential` 只填写 `provider-main`，不填写密钥。定义校验拒绝嵌入模型密钥字段和工作区根路径；定义导出只包含句柄。部署文件不得提交进仓库。首版没有 Secret Vault、多人认证或远程公开部署能力，HTTP 入口只监听本机回环地址。

## 执行、修改与恢复

| 项目         | 已实现行为                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 单次计算     | 每个 Core 调用一次模型，不向其提供工具                                                                   |
| 有界工具循环 | 推理、工具执行、观察分离，所有 Core 与流程直接工具调用共用整次运行的工具步数上限；耗尽后仅允许收尾计算   |
| 时长         | 限制运行活动时长，人工等待和暂停不消耗活动时长；恢复后继续累计                                           |
| 工具访问     | 工具可在流程中直接调用，或供 Core 自主选择。同一个工具节点只能选一种方式；工具只能取得其声明和绑定的资源 |
| 定义修改     | 乐观版本检查；保存产生新版本，不修改已有运行的定义快照                                                   |
| 实例         | 定义可重复实例化，状态、资源对象和文件工作区按实例隔离                                                   |
| 操作回执     | 调用前持久写入意图，调用后保存回执；已完成操作在续接时直接读取回执                                       |
| 人工等待     | 等待操作 ID、提示和上游输出持久保存；结果提交与继续运行在同一事务中完成                                  |
| 重复回调     | 同一操作、相同结果幂等确认；跨运行操作 ID 或冲突结果拒绝                                                 |
| 暂停         | 当前已获准调用可以交回结果，后续调用停止；用户显式继续                                                   |
| 取消         | 运行保持终态，并发出 AbortSignal；不会声称撤销已经发生的外部副作用                                       |
| 中断         | 已开始但无确定回执的操作变为 unknown，等待核验，不自动重做                                               |
| 受控卸载     | 活跃调用和未完成运行依赖的组件版本不可卸载；已持有调用入口在卸载后失效                                   |

“未知结果”需要用户核验实际副作用，再提交真实回执。未知模型计算的回执形式为 `{"kind":"finish","result":"核验后的结果"}`。这里不承诺外部服务的 exactly-once；保护的是不会因为中断就盲目重放。

部署只允许一个活动进程。正常 SIGINT / SIGTERM 会保存状态并释放 `process.lock`；强杀后，先确认旧进程及其外部工作已停止，再移除状态目录的 `process.lock` 后启动。不得在旧进程仍活动时抢占锁。新的运行数据库无需迁移旧角色、审批或记忆数据。

## 组件范围与扩展

预置 12 个组件：提示词模板、模型 Core、人工等待、输出、工作区读取、工作区新建文件、开始/输入、数据转换、条件分支、互斥汇合、决策计算、HTTP 请求。文件写入禁止覆盖已有文件，读取和写入限制在实例工作区，拒绝路径逃逸和符号链接。首版不包含任意终端执行。

可信开发者通过 `ComponentRegistry.register()` 添加组件，声明固定 ID / 版本、输入输出类型、配置校验、资源角色和执行函数。组件版本发布后不得更换同版本实现；变更应注册新版本。组件需要响应 AbortSignal；不响应的组件会失去运行准入，但底层副作用仍须核验。运行中的定义不可任意热迁移。

本版复用了旧有界计算循环的设计，当前实现位于 `packages/lykoi-composer/src/cognition.ts`，旧包已删除。能力生命周期和任务回执/恢复机制以新接口重建，并移植其关键行为测试；没有引入旧 Kernel、Persona、Mind、Converse 或审批全局状态。

## 节点画布操作

组件库、已保存定义、Agent 设置从左侧工具栏展开，选中节点打开右侧配置。点击顶部“试运行”展开底部输入/输出与时间线；可以收起继续编辑。执行策略和资源属于整个 Agent，在“设置”面板中修改。

- 拖动节点标题移动；拖动空白区域、中键或空格加拖动平移；滚轮及缩放按钮缩放。
- 从输出端口拖到输入端口连线，也可依次点击两个端口；Esc 取消。条件节点有多个具名输出端口；互斥汇合不会替换已有输入。工具可在右侧选择“流程直接调用”或“供 Core 自主调用”；后者由 Core 勾选绑定，虚线表示调用关系。
- 点击连接再按 Delete，或在连接面板删除；支持撤销/重做，快捷键 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z。输入字段保持原生文本快捷键。
- 双击空白打开组件搜索，在该位置添加；“自动排列”重排依赖层级，“适应画布”调整视口。
- 布局随保存版本与 JSON 导出保留；编辑布局也需保存新版本后发起新的运行。运行中的旧版本不会被改动。视口平移缩放本身不阻止继续运行，下一次保存时记录当前视口。

源码研究与选择依据见 [composer-ui-research.md](composer-ui-research.md)。

## 语义路由与 JEV

顶部“语义路由”加载一个可展开修改的预设：开始 → 决策 → 条件分支 → 快速 Core / 深度 Core / 人工审核 → 互斥汇合 → 输出。

1. 保存、创建实例，填写 `task` 运行。默认是**手动决策夹具 + 离线生成模型**，只验证装配与分流，不理解任务，也不产生真实模型结果。
2. 在“设置”找到 `router` 资源。手动答案中的 `choice` 决定 `fast/deep`；`confidence` 达到条件阈值才自动执行。将它调低，可验证人工等待。这里的阈值是产品示例，不是经数据评估确定的生产阈值。选中决策节点，展开“本次运行输出”可检查答案、概率与置信度。
3. 切换提供方式为 JEV，完整接口地址为 `https://api.typesafe.ai/v1/systemone`，模型名 `jev-latest`，凭证句柄如 `jev_key`。在仓库外部署 JSON 的 `credentials.jev_key` 提供实际密钥。
4. 分别配置 `fast_model/deep_model` 为实际生成模型。修改决策节点的候选描述、条件阈值与端口连接，然后保存新版本。
5. 服务明确报错/回执格式错误时，配置 `onError: "fallback"` 会返回 `{answers:{},error:"decision_unavailable"}`，交给默认路线；部署配置错误会直接失败。整次运行截止/取消后不继续执行兜底节点。未确定的中断操作仍需核验，不自动重发。

JEV 适配依据官方 [API Reference](https://docs.typesafe.ai/api)（2026-10-01 查阅）：POST 请求含 `model/state/questions`，结果含 `answers`。支持 Choice、Score、Noul；Choice/Score 校验置信度、概率分布和候选范围。`confidence` 是分布集中程度，不能当作实际正确率。`decision-compatible` 表示使用相同请求与回执协议的其他服务；嵌入运行时也可通过 `ResourceFactory` 提供自己的 `DecisionModel.decide()`。

### 数据与控制语义

- 连线控制准入和顺序；`node.input` 可通过 `{"$ref":{"node":"start","path":["task"]}}` 引用原始任务，也可嵌套组装 JSON 对象和数组。`$input` 引用整次运行输入。配置模板支持 `{{input}}`、`{{input.field}}`、`{{nodes.start.task}}`。保留 JSON 类型，拒绝未来/非上游节点引用和保留字段路径。
- 条件按顺序匹配，一个出口内条件是 AND；缺少被比较字段视为不命中，也可显式用 `exists/missing`。默认出口兜底。分支输出保留 `{branch,value}`，下游默认取得 `value`；未选中路线及其后继持久记录 `skipped`，不会创建工具调用意图。
- 互斥汇合读取唯一活跃输入，不把多个并行/独立结果拼在一起；多活跃输入报错。若最终输出被跳过，运行报错。带开始节点的新图要求所有流程节点可从开始到达；旧无开始节点定义保留原有根节点行为。
- Core 可选择 JSON 输出并校验 Schema。Schema 仅支持 `type/properties/required/items/enum/additionalProperties`，其他关键字拒绝，不执行任意代码。人工输入开启结构化审核后按 Schema 展示字段和决策选项，回调同样校验。
- 新添加的工作区工具默认直接调用。直接工具与 Core 工具共用 `maxActions`；HTTP 步骤受节点数量与活动时长约束。HTTP 只接受绑定服务前缀内的相对路径，传输 JSON，拒绝重定向；JEV/HTTP 响应最大 1 MiB。不支持在节点里填写任意认证头或密钥，凭证通过资源绑定注入。

决策 API 目前由测试夹具验证请求与回执协议；未使用所有者真实凭据进行 JEV 线上准确率、时延或费用测试。
