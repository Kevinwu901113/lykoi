## 任务

### 1. 成熟度矩阵

对 8 个包（surface / cognition / core / mind / kernel / shared / memory / resources）+ guardian + scripts，逐个给出：

| 维度 | 判据 |
| --- | --- |
| 功能完整度 | 相对白皮书目标架构，已实现多少 |
| 测试覆盖 | 有无专用测试、覆盖关键路径与否（看文件对应关系，不跑测试） |
| 接口稳定性 | 被多少模块依赖；改动波及面 |
| 设计债 | 硬编码、单例、全局状态、过度设计、抽象缺失 |
| 白皮书对齐 | 与目标架构一致 / 需调整 / 冲突 |

每格给证据（路径:行号或统计）。

### 2. 三分类

每个模块归入一类并给理由：

- **可保留**：设计与白皮书目标一致，可直接进入下一阶段
- **待重构**：功能需要但当前实现挡路（列出具体挡在哪，例如缺 user_id、全局单例、无隔离层）
- **可删除**：过度设计、废弃、或被白皮书明确排除

### 3. 重构阻碍点

按白皮书结论章的三大缺口，逐条列出实施时会撞上的现有代码约束：
a. 群成员身份解析与用户记忆（user_id 作用域）——当前哪些表/接口/单例假设了单用户？
b. 专业 Agent 委托与隔离（Delegation Gateway）——当前 dispatch/权限层缺什么挂载点？
c. 程序性学习与可靠性积累——当前有无可复用的经验存储结构？

### 4. 过度设计候选

指出为未实现能力预留、但至今无生产调用者的结构（用 grep 交叉验证，说明验证方式）。这类代码在重构时是负债而非资产。
