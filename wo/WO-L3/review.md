## 二、代码审阅要点（全部合格）

1. **中文方案**：字符 bigram + 相邻链超线性打分（链长 c → 2c−1），无分词依赖。
   判别力在词一级（"睡眠"不中"睡衣"），有测试钉死。**盲区清单诚实且写进代码注释**
   （单字关切不召回、跨词边界孤立 gram 低分入候选、无同义召回留给向量升级、
   简繁不通、全角英文在 SQL 预筛的窄口）。
2. **通配符防越权是双层结构性保证**：`%`/`_`/`\` 在切段时即分隔符（进不了词项）
   + LIKE ESCAPE 字面转义；另有结构性断言"送去 LIKE 的词项永不含通配符"。
3. **可替换接口**：签名+返回结构即契约，相关性算法收在两个私有函数内，
   向量升级不动调用方。无类继承体系。
4. **两处设计判断均认可**：实体轴硬过滤（语义与 `archive_search` 一致，跨人回想
   就不传 `subject_user_id`）；榨不出词项不回退"最近 N 条"（防"没读懂"伪装成
   "都相关"，防 `%` 标题看似通配全档案）。
5. `match_reasons` 是从命中链还原的真实原文片段，满足 §3.7 血缘回溯前置。
6. 预筛与打分口径一致性有注释论证（预筛宽于打分只多算行，窄于打分才丢召回）。
