## 二、逐条查了什么

1. **音频硬边界（Kevin：「跟音频相关的都不做」）——守住了。**
   `cli.py:97` 的总闸 `audio_enabled = _env_bool("LYKOI_AUDIO_SENSE_ENABLED", False)`
   **只读环境变量、默认 False、不在 config schema 里**，且旁边有注释写明这是刻意的
   （standalone 服务永不开音频；裸 CLI 默认关是因为 Speech/Microphone TCC 查的是
   责任进程的 usage description，终端没有 → 子进程被 SIGABRT，2026-07-06 实测崩溃循环）。
   麦克风/系统音两个子闸都是 `audio_enabled and ...`，总闸关则必关。

2. **配置权限位**：`load_service_config` 对 `mode & 0o077` 直接抛错并给出修复命令。
   未知键**拒收**（allow-list），类型逐个校验。这两条都有测试。

3. **token 不落盘**：`resolve_token()` 走 `/usr/bin/security find-generic-password -w`；
   config 里的 inline `token` 只服务于 mock 端点。`cli.py:86` 注释写明"永不来自明文环境变量"。

4. **互斥**：`single_instance.py` 用 `flock(LOCK_EX|LOCK_NB)`，**进程死锁自动释放**
   （不留陈旧锁），文件里的 JSON 只是给日志看的 advisory 信息——互斥体是 flock 本身。
   败者 `exit 0` + plist `KeepAlive.SuccessfulExit=false` 防止监督者狂拉。设计正确。

5. **配置优先级**：CLI > env > config.json > 内置默认，有测试锁死；
   `test_app_embedded_env_still_wins` 保证 app 内嵌模式零回归（监督者注入的 env 永远压过文件）。

6. **出厂端点是本地 mock 8799**——改真端点是一次显式人工编辑，不会意外外发。这条我认可。

## 三、一处措辞不准（不影响结论）

M1A 报告写「**音频不在 schema 里**（硬边界）」。准确说法是：
**音频总闸不在 schema 里**（这才是硬边界的实质）；但 `speech_locales`（纯音频参数）与
`muted`（全局感知闸，屏幕也用）**在 allow-list 里**。

- 二者的默认值与 M1A 之前的环境变量默认值**逐字相同**（`False` / `["zh-CN","en-US"]`），
  没有改变任何默认行为；总闸关时 `speech_locales` 根本不会被读到，是死参数。
- 所以**不构成对 Kevin 硬边界的违反**，但报告那句话该改。
- **建议（不阻塞合并）**：把 `speech_locales` 从 `_ALLOWED_KEYS` 移除。
  它是纯音频参数，留在 standalone schema 里没有用途，删掉能让"硬边界"这句话字面为真。
  一行改动、零风险。等 M1b 定了 Mac 最终形态再一并做也行。
